+# Code of Conduct
+
+## Our Pledge
+
+We want participation in this project to be a welcoming, harassment-free experience for everyone, regardless of age, background, experience level, identity, or beliefs.
+
+## Expected Behavior
+
+- Be respectful and considerate of others
+- Give and accept constructive feedback gracefully
+- Assume good intent, and ask for clarification before assuming otherwise
+- Focus on what is best for the project and the community
+- Credit others for their work and ideas
+
+## Unacceptable Behavior
+
+- Harassment, insults, or personal or political attacks
+- Discriminatory jokes or language
+- Trolling, deliberate disruption, or spam
+- Publishing someone's private information without permission
+- Any other conduct that would reasonably be considered inappropriate in a professional setting
+
+## Scope
+
+This Code of Conduct applies in all project spaces, including issues, pull requests, discussions, and comments, and when someone is representing the project in public.
+
+## Reporting
+
+If you experience or witness unacceptable behavior, report it to the maintainers by opening an issue, or by contacting the repository owner through their profile if you'd prefer privacy. All reports will be reviewed and handled fairly and promptly. Maintainers will respect the privacy of anyone who reports an incident.
+
+## Enforcement
+
+Maintainers may remove, edit, or reject comments, commits, issues, and other contributions that violate this Code of Conduct. Depending on severity, they may issue a warning, temporarily restrict participation, or permanently ban a contributor from the project.
+
+## Attribution
+
+This Code of Conduct is adapted from the [Contributor Covenant](https://www.contributor-covenant.org), version 2.1.

+# Contributing to Git-Scripts
+
+Thanks for your interest in contributing! This guide explains how to report issues, propose changes, and get your work merged.
+
+## Code of Conduct
+
+By participating, you agree to follow our [Code of Conduct](CODE_OF_CONDUCT.md). Please be respectful and constructive.
+
+## Ways to Contribute
+
+- **Report bugs** by opening an issue
+- **Suggest features** or improvements
+- **Improve documentation** (typos, examples, clarity)
+- **Submit code** for bug fixes or new features
+
+## Reporting Bugs
+
+Before opening an issue, search existing issues to avoid duplicates. A good bug report includes:
+
+- A clear, descriptive title
+- Steps to reproduce the problem
+- Expected vs. actual behavior
+- Your environment (OS, version, runtime, etc.)
+- Logs, screenshots, or a minimal code sample if possible
+
+## Suggesting Features
+
+Open an issue describing the problem you want to solve, your proposed solution, and any alternatives you considered. For large changes, please discuss before writing code so we can agree on direction.
+
+## Development Setup
+
+1. Fork the repository and clone your fork:
+```bash
+	git clone https://github.com/RuslOFFICIAL/Git-Scripts.git
+	cd Git-Scripts
+```
+2. Create a branch:
+```bash
+	git checkout -b feature/short-description
+```
+
+## Making Changes
+
+- Keep changes focused. One pull request should address one concern.
+- Follow the existing code style.
+- Add or update tests for any behavior you change.
+- Update documentation when relevant.
+
+## Submitting a Pull Request
+
+1. Push your branch to your fork.
+2. Open a pull request against the `main` branch.
+3. Fill out the PR template, linking any related issues (e.g. `Closes #123`).
+4. Make sure all CI checks pass.
+5. Respond to review feedback. A maintainer will merge once it's approved.
+
+### PR Checklist
+
+- [ ] Tests added or updated
+- [ ] Linting passes
+- [ ] Documentation updated
+
+## Review Process
+
+Maintainers aim to respond within a few days. Reviews may request changes; this is a normal part of the process and not a judgment of your work.
+
+## Licensing
+
+By contributing, you agree that your contributions will be licensed under the project's [LICENSE](LICENSE).
+
+## Questions?
+
+Have a question? Open an issue or start a discussion in the repository. We're happy to help first-time contributors get started.
